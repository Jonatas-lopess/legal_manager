# Deadline engine reads plain columns, not a type catalog or tags

Considered a tenant-editable `deadline_types` catalog (mirroring `matter_catalog_items`) to hold the fatal/não-fatal and dias-úteis/dias-corridos attributes the counting engine needs. Rejected: it's a join + lookup for two booleans, and it tempts the engine to read tenant-editable rows for logic that must stay reliable. Instead, `is_fatal` (bool) and `counting_mode` (`dias_uteis`/`dias_corridos`) are plain columns on `deadlines`, read directly by the engine. Freeform labeling (legal act name, urgency, anything cosmetic) reuses the existing `tags`/`matter_tags` pattern extended to `deadlines`, but tags are never read by the counting engine — only by reports/filters. This keeps the differentiator's correctness independent of anything a tenant can freely edit.
